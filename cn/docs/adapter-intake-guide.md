# 新 App 适配采集指南（adapter intake）

目标：为一个新聊天 App 收集足够素材，让产出的适配器达到仓库自带适配器（QQ / X / 飞书 / WhatsApp）的水准。

自带适配器的「水准」具体指什么（对照 `capture/ChatAppAdapter.kt` 顶部注释与 `cn/CLAUDE.md` 实测结论）：

1. **三态契约零误判**：不在聊天窗 → `null`；在聊天窗但没正文 → 空快照（这是 OCR 兜底的唯一触发条件）；有正文 → 正常快照。任何其他页面（列表、资料、动态、设置）绝不能误判成聊天窗。
2. **「我/对方」归属在边界情况下仍正确**：长消息中心过半屏、短消息、纯表情都不能判反。
3. **杂质全排除**：时间戳、日期分隔条、系统提示、未读分隔线、昵称、头衔、广告横幅不进消息列表。
4. **滚动稳定**：上下翻历史不产生重复/抖动，签名去重可靠。
5. **OCR 兜底就绪**（树里没正文时）：能给出气泡矩形列表和每条的气泡归属。
6. **填入可用**：输入框是标准可编辑节点，`setText` 或剪贴板粘贴至少一条路通。
7. **有据可查**：每个结论标注 App 版本、设备、日期；录屏/dump 数据入库做回归单测。

采集原则：**每一个结论都要有一份对应的原始素材（XML dump + 截图）佐证**。宁可多采，不要凭印象补。

## 1. 快速可行性初筛（先做，30 分钟，不行就止损）

在投入完整采集前，先回答三个一票否决的问题：

1. **截屏是否被禁**：在聊天窗手动截屏。黑屏 / 提示禁止截屏（`FLAG_SECURE`）→ OCR 兜底路断，若树里也没正文则整个放弃。
2. **树里有没有正文**：在聊天窗执行 `adb shell uiautomator dump`，拉下来搜一条你刚发的消息原文。搜得到 → 走规则路线（最省事）；搜不到 → 确认是「自绘/Flutter」型，走 OCR 路线（参考飞书），采集重点改为气泡矩形和归属信号。
3. **输入框是否标准**：dump 里找聊天窗底部的输入框节点，确认是 `EditText` / `isEditable=true`。是 → 填入链路大概率通；不是 → 记录下来，填入可能要特殊处理。

## 2. 包名与页面地图

```bash
# 打开目标页面后执行，拿包名和 Activity 名
adb shell dumpsys window | grep -E "mCurrentFocus|mFocusedApp"
```

对 App 内每个主要页面各记一次（聊天窗 / 会话列表 / 首页 / 资料页 / 设置）：
- 如果**所有页面都是同一个 Activity**（QQ 的 SplashActivity、X 的 MainActivity 都是这个形态），记录结论「不能按 activity 判窗，只能看树」；
- 如果聊天窗有独立 Activity，也要记录——它是「在聊天窗」的强信号之一，但不能单独依赖（fragment 化改版随时会来）。

## 3. 页面 × 状态采集矩阵

每个样本是**三件套**：`uiautomator dump` 的 XML + 同画面截图 PNG + 一行备注（画面里发生了什么）。先截屏再 dump，保证两者对应同一瞬间。

```bash
adb exec-out screencap -p > qs-01-chat-normal.png
adb shell uiautomator dump /sdcard/qs-01.xml && adb pull /sdcard/qs-01.xml qs-01-chat-normal.xml
```

### A. 聊天窗（采集重点，至少 10 组样本）

| # | 状态 | 目的 |
|---|---|---|
| A1 | 正常多轮对话（双方各几条） | 正文节点、归属判据的基本形态 |
| A2 | 一条**超长消息**（多行、气泡中心越过屏幕中线） | 验证归属判据不被中心点骗（QQ 踩过：长消息中心过半屏，要贴头像列比距离） |
| A3 | 极短消息：单字、纯表情、emoji | 过滤规则不能把它们误当杂质丢掉 |
| A4 | 空对话（刚匹配/刚加好友，一条消息都没有） | 「在聊天窗但无正文」的空快照形态，触发 OCR 的判据 |
| A5 | 含时间戳 / 日期分隔条的画面 | 杂质特征 |
| A6 | 含系统提示的画面（如「对方开启了已读回执」「你们已成为好友」） | 杂质特征，常无 resource-id |
| A7 | 含非文字消息：图片、语音、视频、名片、链接卡片 | 决定跳过还是占位（占位文案如「[图片]」还是整条丢弃） |
| A8 | 含引用 / 回复消息 | 嵌套结构是否重复采到引文（X 踩过：附件行嵌套引用帖 TextView，只采行自身） |
| A9 | 上滑加载了历史消息的画面 | 滚动后树的形态；虚拟化列表的节点复用是否影响去重 |
| A10 | 键盘弹起状态 | 底部输入区形态变化；OCR 裁剪带的下边界依据 |
| A11 | 输入框已打字未发送 | 输入框内容与消息正文不能混淆 |
| A12 | 顶部瞬态状态（如「连接中…」「对方正在输入…」） | 标题污染防护（v1.3 踩过：瞬态标题污染会话记录） |
| A13 | 新消息刚到达的瞬间（对方发来后立刻 dump） | 验证事件驱动刷新时机；签名去重是否会把新旧混一起 |

### B. 负样本页面（同样重要，每页一组）

这些页面 `extract` 必须返回 `null`。漏采 = 上线后误触发分析/OCR：

- B1 会话列表页（它的行经常长得**非常像**消息行——X 的列表行和消息行同为全宽 View + desc，靠 `, @` 特征才区分开；重点对照）
- B2 首页 / 推荐 / 匹配页
- B3 对方资料页
- B4 动态 / 广场页
- B5 设置页
- B6 搜索页（注意：搜索框也是 EditText——X 踩过：列表页搜索框会被误判成「有输入框 = 在聊天窗」）

### C. 红线区域（采集但标注「禁止触碰」）

- C1 充值 / 会员购买页
- C2 礼物面板、打赏弹窗
- C3 任何含支付按钮的画面

这些素材的用途是**让适配器认得它们并避开**：不读、不点、不在这些页面显示悬浮球（对照 `ChatCaptureService` 的 `BLOCKED_PKGS` 机制）。采集后建议在文件名里加 `BLOCKED` 前缀。

### D. OCR 路线补充采集（仅当 §1 判定树里没正文时）

- D1 气泡容器节点长什么样（resource-id 或稳定类名），dump 里量出矩形
- D2 「我」的气泡有什么独有标记（飞书的依据：只有自己气泡挂「已读」条 `time_read_state_container`）；如果没有任何标记，记录「归属只能靠几何/头像列」，并多采几组左右布局样本
- D3 列表虚拟化行为：快速来回滚动后 dump，看气泡节点是否复用/错位（影响 OCR 重读矩形的时机，v1.3 修过截屏回调里要按回调时刻重读矩形）

## 4. 行为探针（不用 dump，记录观察结论即可）

1. **滚动重排**：聊天窗里缓慢滚动 vs 快速滚动，树是否整体重排（影响去重签名设计）。
2. **事件频率**：对方连续发 3 条消息，观察悬浮球刷新是否跟得上、有没有抖动。
3. **前后台切换**：切走再切回，会话是否被正确识别为「同一会话」。
4. **多窗口 / 分屏**：聊天窗在分屏下的矩形坐标是否仍准确（截屏按窗口坐标缩放，v1.3 修过这个）。
5. **填入链路**：手动验证——目标 App 输入框能否被无障碍 `ACTION_SET_TEXT` 写入；不行则验证剪贴板粘贴路径。（只验证到「文字进输入框」，**发送永远手动**。）

## 5. 脱敏（交付前必做）

聊天记录属于个人隐私，入库前必须处理：

- XML 和 PNG 里的人名、昵称、头像、聊天正文统一替换为占位符（如「对方A」「测试消息一」）；
- PNG 头像区域打码；
- 全文检查不含手机号、微信号、任何 `sk-` 开头的密钥串；
- 脱敏后再核对一遍 XML 仍能被解析（替换时保持 XML 转义合法）。

## 6. 交付格式

按 App 版本归档（对照 `global/fixtures/screendumps/whatsapp-2.26.38.73/` 的惯例）：

```
qianshou-<versionName>/           # 例：qianshou-3.2.1/
├── README.md                     # §0 环境表 + 每个样本文件的一行说明
├── qs-01-chat-normal.xml / .png
├── qs-02-chat-longmsg.xml / .png
├── ...（A/B/C/D 各组样本）
└── notes.md                      # §4 行为探针的观察结论
```

采集阶段放 `cn/_intake/qianshou/`；适配器落地时，精选样本移入 `app/src/test/resources/qianshou/` 作为回归测试 fixture。
